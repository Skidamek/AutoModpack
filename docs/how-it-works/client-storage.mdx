# Client storage

The client keeps pack files in a content-addressed store, keyed by hash. When two generations ship the same jar, the store holds one copy of the bytes.

On top of that sit the pack-history mirror (the server's published generations), the live projection the game loads from, overlays for editable files, and the instance timeline.

## Instance timeline

The Instance timeline lists snapshots this Minecraft instance actually lived. Each snapshot is the tracked files plus the live identity (active pack, selection, overlays) at that moment. Restore puts the running instance back to that snapshot. It does not talk to the server. Every installed pack stays in the pack list and is detached, so the next join cannot overwrite the restore until you sync.

Files on a snapshot show what changed from the previous snapshot. You can save a copy of any file. Restore of a single file only writes into the game folder when that path is free.

Forget older than this drops older snapshots on this computer and then unpins file data nothing else still names. That is the retention control for the timeline. Clean local storage does not drop timeline snapshots.

## Clean local storage

Cleaning is the explicit pass for **pack history** objects that the instance timeline does not pin. Per pack it keeps the active generation and the newest generation, plus every generation's policy document. File data that only older generations still name, and that no instance snapshot names, is deleted.

A clean refuses to run while an update transaction is active. After it finishes, the screen shows one receipt per pack: the date of the clean, the generation it cleaned through, and how much was reclaimed. Pack-history restore of those older generations then shows as not kept on this computer.

Instance timeline snapshots keep their bytes until you use Forget older than this on the timeline.

## How big does this get

The store grows as you use the pack. New generations, timeline snapshots, and repairs all add objects, and nothing is pruned automatically. The store has no size cap.

Reclaiming space is manual, and three paths do it. Clean local storage reclaims the pack-history bytes that only older generations still name. Forget older than this reclaims the timeline bytes that older snapshots still pin. Removing a pack in the Modpacks list deletes that pack's records and then collects the objects that nothing else names.

## Verify storage

Verification checks every object the pack and the instance timeline reference and reports how many are present and valid. It runs in the background and keeps running when you leave the screen.

## Repair

If files are corrupted or the game crashes on load, the Modpack Settings screen offers Repair. Repair re-checks the local storage and re-downloads what does not match. For editable files it offers to keep the player's changes, per file.

## Pack history, restore, and stop syncing

Pack history is the server catalog of one pack: generation number, date, notes, and the pack file diff. The published patch notes of each generation are visible there. It is not the instance timeline. Apply of an older generation uses files already in the local store. The server does not send historical generation objects; it serves the latest generation.

Restoring a pack-history generation, or an instance snapshot, detaches the pack so the server cannot immediately overwrite it. Stop syncing does the same from the pack manager: your files stay as they are. Sync now reattaches and applies the server's current generation.
