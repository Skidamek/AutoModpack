## Version sync and switching

The server can publish the versions a pack needs: the modloader type, the modloader version, and the Minecraft version. Publishing is controlled by `advertiseVersionsToSync` in the [server config](../configuration/server-config) (named `syncLoaderVersion` before v5).

AutoModpack applies that metadata to the launcher instance itself on Prism, MultiMC forks, Pandora, and CurseForge app instances. A loader-version bump is applied the same way as in v4. A pack switch that needs a different Minecraft version or a different modloader rewrites the launcher's instance metadata, and the change is picked up on the next launch. On CurseForge the switch also restarts the CurseForge agent, which is expected.

Before changing anything, AutoModpack asks the Prism meta server whether it knows the target versions. If it does not, the versions are left alone rather than risk installing something the launcher cannot resolve. Server owners can stop publishing version metadata entirely with `advertiseVersionsToSync: false`, and players can refuse the sync per instance with `syncLoaderVersion: false` in the [client config](../configuration/client-config).

AutoModpack cannot switch launchers it does not manage: the vanilla launcher, Modrinth App, ATLauncher, and custom instances. A pack that needs different versions is then not applied at launch. The client says which versions to change by hand before the next start. Joining the server in-game still syncs the pack files.
