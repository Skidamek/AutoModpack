# Commands

 Assume all commands below are prefixed with `/automodpack`, `/amp` is a shorthand for `/automodpack`. Commands run on the server console or in-game with operator permission level 3.

## Publishing

- `generate` - Publishes a new generation when the pack files or rules changed. A changed `waiting-music.ogg` is published too, even when the pack content is otherwise the same.
- `generate notes <text...>` - Publishes a generation with patch notes.
- `generate preview [notes <text...>]` - Builds the next generation and reports what would change, without publishing.
- `generate if-content <content-token> [notes <text...>]` - Publishes only while the content still matches the given token, so a scripted publish cannot race a manual change.
- `generate history` - Prints the newest hundred journal entries with sequence number, date, change summary, and patch notes.
- `generate revert <seq>` - Previews a rollback to journal sequence `<seq>`.
- `generate revert <seq> confirm [notes <text...>]` - Publishes the selected old state as a new generation.
- `generate storage` - Reports how many bytes the journal and the object store hold.
- `generate export-http [--all] <directory>` - Writes the URL-contract tree (`head`, `journal`, `objects/<sha1>`) as byte-for-byte copies of the hosted files, ready for any static HTTPS host. Objects Modrinth or CurseForge still serve themselves are left out; `--all` keeps every object in the tree. The command reports what was exported, omitted, and unresolvable. Works in every connection mode and never deletes anything from the directory.
- `generate storage collect confirm` - Deletes every object the current generation does not serve. Older generations stay listed in the journal but can no longer be restored.

Patch notes for the next publish can also be written to `automodpack/host-modpack/patch-notes.md`; the file is read and cleared when a generation publishes. Publishing, rollbacks, and storage are explained in [generations](how-it-works/generations).

## Hosting

- `host` - Hosting status.
- `host start`, `stop`, `restart` - Control the modpack host.
- `host activity` - Shows modpack request activity since startup: totals, recent transfers, in-flight downloads; hover for per-player stats.
- `host fingerprint` - Prints the [certificate fingerprint](security#how-clients-verify-a-server) of the modpack host.
- `host fingerprint dns <minecraft-hostname>` - Prints a DNSSEC record that lets clients verify a self-signed certificate automatically.
- `host bootstrap pin <origin> [name <server-name>]` - Writes `automodpack/automodpack-bootstrap.exported.json` with a TLS pin, for distributing to clients. The optional server name also adds the pack to the client's server list.
- `host bootstrap install <origin> [endpoint <endpoint> <connection-mode>] [name <server-name>]` - Writes an install export with the published pack, a provisioning secret, and the endpoint clients download from. Requires `disable-internal-tls` to be off.

Without an explicit `endpoint`, the export advertises `advertised-endpoint-host` and `advertised-endpoint-port` when they are set. Otherwise the host is the origin, and the port follows the connection mode: HOLEPUNCH uses the Minecraft port, MAGIC uses `bind-port` when set and the Minecraft port otherwise, and HTTP requires `bind-port`. An explicit `endpoint` always wins.

Both bootstrap exports contain trust data or a provisioning secret. Treat them like credentials; anyone holding one can provision themselves onto your pack. See [bootstrap files](how-it-works/files-on-disk#bootstrap) for how clients import them.

## Inviting players

- `invite <minecraft-address>` - Prints copyable join addresses for players. With local TLS it prints the pinned AutoModpack address, the plain Minecraft address, and the `host bootstrap install` command for one-file setup. When `disable-internal-tls` is on, it prints the plain address and says there is no AutoModpack fingerprint to pin. When the advertised endpoint is served by a reverse proxy or tunnel, it prints the plain address and says clients verify against that front-end's certificate.

## Configuration

- `config reload` - Reloads the server config. When connection settings changed, it tells you to run `host restart` to apply them.

## Groups

- `groups` - Lists every modpack group under its category, with published file counts and sizes.
- `groups <group-id>` - Shows one group's flags, dependencies, glob rules, and the files its published generation carries.
