### Encryption

Modpack download connection is secured using TLS 1.3.

This is the same security standard used by HTTPS, the protocol which you're using all the time to browse the web (even now!).

TLS has method of verifying the server's identity using a certificate which is crucial to prevent attacks such as [Man-in-the-middle](https://en.wikipedia.org/wiki/Man-in-the-middle_attack).

AutoModpack treats the original Minecraft hostname selected by the player as the server identity. SRV targets, server transfers, and the server-advertised modpack address and port do not replace that identity; they are routing information only. A CA-signed certificate must be valid for the original Minecraft hostname, while clients can authenticate a self-signed certificate through a DNSSEC fingerprint under the same hostname. When neither automatic method is available, AutoModpack uses permanent origin-scoped fingerprint trust. Read [certificate verification](certificate) for setup and fallback details.

### Connection modes

Every mode establishes an AutoModpack TLS session, but each uses a different opening:

```text
HOLEPUNCH     Minecraft Handshake/Login takeover → TLS → AutoModpack protocol
MAGIC_PACKET  AMMH → AMOK → TLS → AutoModpack protocol
DIRECT        TLS → AutoModpack protocol
```

The modes are strict and clients do not retry another mode after failure. On a shared Minecraft listener, non-AMMH traffic is returned to Minecraft unchanged. On a dedicated `MAGIC_PACKET` listener, non-AMMH traffic is rejected. A `DIRECT` listener never responds with AMOK.

Optional PROXY protocol metadata may precede dedicated `MAGIC_PACKET` and `DIRECT` connections. It is not consumed by the shared Minecraft-port handler.

`disableInternalTLS` changes only where the required TLS session is terminated. Clients still start TLS; when internal termination is disabled, a compatible external component must decrypt the connection before forwarding AutoModpack protocol traffic.

### Direct Downloads

AutoModpack uses direct download links from Modrinth and CurseForge APIs to download most of your modpack files.
This means that the mod authors get credit for every download.

However, if file you are providing in the modpack is not available on Modrinth or CurseForge, AutoModpack will download it (also directly) but from your server.

### Compression

To speed up downloads, AutoModpack uses pure-Java [Zstandard](https://facebook.github.io/zstd/) compression by default.
The transfer protocol also defines None, Gzip, Snappy, LZ4, and LZO codecs; peers select one codec for the connection before file frames begin.
Zstandard offers the best general compression ratio and performance for modpack transfers without shipping or extracting native binaries.
Compression applies only to files downloaded from your server.

### Authorization

<Callout>
Do not confuse this with [certificate fingerprint verification](certificate), which is used to verify the server's identity.
</Callout>

AutoModpack uses a simple authorization mechanism to prevent unauthorized access to your modpack.
When you connect to the server, in the background AutoModpack generates a random unique secret for each player. This secret is then send to the player and used to authorize the player to download the modpack files.
Every time you reconnect to the server, the old secret is invalidated and a new one is generated.
This prevents unauthorized access to your modpack files and ensures that only whitelisted and not banned players can download the modpack.
If you don't want to use this feature, you can disable it (`validateSecrets`) in the [server config](../configuration/server-config).
