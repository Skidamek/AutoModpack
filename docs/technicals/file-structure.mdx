All the AutoModpack files are kept inside `~/automodpack/` folder.

## Server
Modpack is generated from files inside `~/automodpack/host-modpack/main/` and/or `syncedFiles` (read [config](../configuration/server-config)) which both translate to `~/.minecraft/` (root minecraft instance) folder on client.

Modpack generation means creation of `~/automodpack/host-modpack/automodpack-content.json` which contains metadata of every single file of the modapck. You **should NOT** touch this file manually, edit config instead.

## Client
Client generation records, overlays, baselines, transaction workspaces, recovery archives, and the fixed active projection are kept inside `~/automodpack/client/`.

The client pins its content-addressed data root in `~/automodpack/data-root.json`. A normal installation may use the shared platform data directory; when that is not available, it falls back to `~/automodpack/data/`. The pinned data root contains `objects/` and the derived client caches. The autotester pins this root to `~/automodpack/client/data/` so a scenario is self-contained.

The active projection mirrors the selected generation's game-relative paths, including `mods/`. Immutable files are linked from the client CAS when the platform supports it. Editable files use the client overlay only after the player changes them.

The game directory receives live copies for files that the loader or game must read there. Standard `mods/` receives only the AutoModpack loader, loader-required copies, and retained user-owned files. There is no per-modpack client directory.
<Callout>
AutoModpack removes a live file only when its ownership ledger and content hash prove that the file is still managed by AutoModpack. User-owned or edited files are preserved.
</Callout>

### Why an active projection?

The selected generation is materialized into one fixed active projection for three reasons:
1. This way if you (as a modpack/server admin) accidentally make a bad update which would normally make game crash on launch and require manual intervention, you can fix it remotely because modpack is updated before it's loaded, that's not possible to do when all mods are loaded immediately by loader in the default mods folder.
2. We can update modpack without requiring restart all the time, if there's a pending update while you were not in game, on launch early, automodpack can update modpack and load it afterward thanks to that you don't need to reboot the game to apply updates.
3. The active projection is independent of generation identity, so switching or recovering a generation changes one well-defined tree instead of maintaining one physical tree per modpack.

Some loader services cannot be discovered from the projection. AutoModpack copies those files to standard `mods/` only when the loader-specific placement rule requires it; `forceCopyFilesToStandardLocation` can request the same placement explicitly.
