# Server configuration

`automodpack/server.toml` in the server root directory. The file is created on the first start with defaults.

The file is standard TOML: comments start with `#`, options are `key = value`, and related settings are grouped into `[tables]`. Comments, blank lines, and formatting are preserved when AutoModpack updates the file.

## Editing the file

Apply changes with `/automodpack config reload` or a restart. When the reload changes connection settings, run `/automodpack host restart` to apply them. A start rewrites superseded keys in the file when it can; a read-only config directory still boots and keeps the old file.

## General

| Setting | Default | Description |
|---|---|---|
| `modpack-host` | `true` | Runs AutoModpack's built-in connection handling. When false, clients still receive connection information, which can point at a proxy or an externally handled endpoint. See [hosting](../how-it-works/hosting). |
| `generate-modpack-on-start` | `true` | Publishes a new generation on every start when the content changed. |
| `require-modpack` | `true` | When true, players without AutoModpack are kicked and modded clients sync the pack before joining. When false, the pack is optional: players without the mod join vanilla, and modded clients are asked whether to sync before they join. |
| `accepted-loaders` | current loader | Extra loaders allowed to join. The set is seeded with this server's loader on first load; this server's loader is always accepted even if you remove it. Unknown names are logged and ignored. Most mods are loader-specific, so change it with care. |
| `advertise-versions-to-sync` | `true` | Advertises the pack's version metadata (modloader, loader version, Minecraft version) to clients. When false, clients treat the pack as files-only and never switch their launcher instance's versions. See [launcher compatibility](../compatibility/launchers#version-sync-and-switching) for which launchers apply it. |
| `self-updater` | `false` | Updates AutoModpack itself from Modrinth when a new version is published. |

## Groups

`[modpack]` holds pack-wide settings (`name`, `auto-exclude-server-side-mods`, `exclude`, `editable`). Optional `[categories.<id>]` sections define display headers and pick modes (`ANY`, `AT_MOST_ONE`, `EXACTLY_ONE`). Top-level `[groups.<id>]` sections define pack groups, where `<id>` maps 1:1 to `automodpack/host-modpack/<id>/`. The factory configuration declares `[groups.main]` (`name = "Core"`, `selection = "REQUIRED"`). You can put files in new folders under `automodpack/host-modpack/<id>/` and run `/automodpack groups import` to create their `[groups.<id>]` blocks in `server.toml`. See [building the modpack](../pack-content).

Category IDs and group IDs are stable keys (`[a-z0-9][a-z0-9_-]{0,63}`, not a Windows reserved device name). The group ID links `requires`, saved player selections, and `automodpack/host-modpack/<id>/`. Changing `name` on a category or group updates what players see without breaking saved selections, `requires`, or folders. If `name` is blank, the UI shows the ID.

### Categories

Define `[categories.<id>]` when you want groups organized under named sections or restricted to exclusive radio choices:

| Setting | Default | Description |
|---|---|---|
| `categories.<id>.name` | `""` | Section header shown on the Group Selection screen. Blank falls back to `<id>`. |
| `categories.<id>.description` | `""` | Short description shown under the category header. |
| `categories.<id>.pick` | `"ANY"` | `ANY` lets players toggle each group independently (checkboxes). `AT_MOST_ONE` shows radio buttons with a `None` option. `EXACTLY_ONE` shows radio buttons and requires one active choice. `REQUIRED` and `AUTOMATIC` groups cannot sit inside an exclusive category. |

Categories and uncategorized groups appear in the UI in declared order. Groups without a `category` render outside named categories (or under an "Other" heading if categories exist).

### Rule lists

All three glob lists are path patterns relative to the game root (forward slashes `/`, leading `!` to negate). Trailing `/**` matches everything underneath cleanly.

| Setting | Factory default | Description |
|---|---|---|
| `modpack.exclude` | `["**/.*", "**/.*/**", "**/*.{tmp,disabled,bak}"]` | Pack-wide exclusion rules applied to every group unless a group negates a pattern with `!`. These rules do not add files. |
| `modpack.editable` | `["options.txt", "config/**"]` | Pack-wide editable file rules applied to every group unless a group negates a pattern with `!`. Listing a path does not add it to the pack. Local edits survive updates until the server changes the file; see [client updates](../how-it-works/client-updates#editable-files). |
| `groups.<id>.from-server` | `["mods/*.jar", "kubejs/**", "emotes/*"]` on `main` | Extra paths pulled from the server root into this group. |
| `groups.<id>.exclude` | `["kubejs/server_scripts/**"]` on `main` | Additional exclusions or `!` exceptions over `modpack.exclude` for this group. |
| `groups.<id>.editable` | `[]` | Additional editable rules or `!` exceptions over `modpack.editable` for this group. |

### Globbing wildcards

A leading `/` is allowed and ignored. Rules are otherwise relative to the server root, with one exception: a rule may name its own group's directory under `automodpack/host-modpack/<id>/`, which is useful for excluding part of it.

- `*` matches within a single directory, for example `mods/*.jar`.
- `**` matches recursively, for example `kubejs/**`.
- `!` negates a rule inside its own list. A path matches a list when a positive rule matches it and no `!` rule does.

Where the negation applies depends on the list it sits in. Inside `from-server` it skips a path from the synced set only, and the group directory may still provide it. `exclude` keeps a path from reaching clients entirely, so prefer it for exclusions and reach for a `from-server` negation only when the group-directory copy should still ship.

Read more about glob syntax on the [Globbing Wikipedia article](https://wikipedia.org/wiki/Glob_(programming)#Syntax).

### Group fields

| Setting | Default | Description |
|---|---|---|
| `groups.<id>.name` | `""` (`"Core"` on factory `main`) | Display name shown to players in the UI; blank shows the group ID. |
| `groups.<id>.description` | `""` (`"Core modpack files"` on factory `main`) | Short player-facing description of the group. |
| `groups.<id>.category` | `""` | Optional ID of a `[categories.<id>]` section to group this entry under. |
| `groups.<id>.selection` | `"OPTIONAL"` (`"REQUIRED"` on factory `main`) | One of `REQUIRED`, `RECOMMENDED`, `OPTIONAL`, or `AUTOMATIC`. `REQUIRED` always installs and stays hidden from checkboxes. `RECOMMENDED` starts selected and lets players opt out. `OPTIONAL` starts unselected. `AUTOMATIC` stays hidden and installs only while a selected group requires it. |
| `groups.<id>.auto-exclude-server-side-mods` | inherits `modpack.auto-exclude-server-side-mods` (`"METADATA"`) | Optional per-group override (`DISABLED`, `METADATA`, or `PLATFORMS`). Omit to follow `[modpack]`. See [Dedicated-server jars](../pack-content#dedicated-server-jars). |
| `groups.<id>.requires` | `[]` | Group IDs that install automatically whenever this group is selected. |
| `groups.<id>.compatible-platforms` | `[]` | Restricts the group to matching platforms, for example a group of Windows-only mods. Empty allows every platform. |

### Migrating from `server.conf` or v4 JSON

If `server.toml` does not exist yet, AutoModpack automatically migrates a v5-rc `server.conf` (or a v4 `automodpack-server.json` / `server-config.json`) into a fresh `server.toml`, including legacy `required`/`default-selected` group flags and pack-level `auto-exclude-server-side-mods`, and renames the old file to `.backup`.

### Platforms

A platform is any short lowercase name. Clients detect `windows`, `linux`, and `macos` automatically and preselect the matching entry in the platform dropdown of the Group Selection screen. Any other name a group declares, for example `steamdeck`, is listed there too, so a player on a detected desktop OS can still opt into it. An empty `compatible-platforms` means every platform.

When a client cannot detect a platform at all, groups without `compatible-platforms` behave as usual and platform-restricted groups stay unavailable until the player picks a platform.

## Network and hosting

| Setting | Default | Description |
|---|---|---|
| `network.connection-mode` | `"HOLEPUNCH"` | One of `HOLEPUNCH`, `MAGIC` or `HTTP` (any case). HOLEPUNCH uses the Minecraft port. MAGIC can share it or use `network.bind-port`. HTTP uses `network.bind-port`. The modes and their port behavior are described in [hosting](../how-it-works/hosting). |
| `network.bind-address` | `""` | Local address for a dedicated listener. Empty binds to all interfaces. Used only when the selected mode starts one. |
| `network.bind-port` | `-1` | Controls built-in listeners according to `network.connection-mode`; see the [mode matrix](../how-it-works/hosting#connection-modes-and-ports). Values unused by the selected mode are preserved. |
| `network.advertised-host` | `""` | Public hostname or IP sent to clients as the download endpoint. Empty uses the hostname the player connected to. |
| `network.advertised-port` | `-1` | Public TCP port sent to clients. `-1` uses the connected port. |
| `network.bandwidth-limit` | `0` | Upload speed limit in MiB/s per client. `0` means unlimited. |
| `network.disable-internal-tls` | `false` | Skips AutoModpack's own TLS termination. Clients always start TLS, so an external terminator must forward decrypted traffic. Expert setting; see [hosting](../how-it-works/hosting#tls). |
| `network.accept-proxy-protocol` | `false` | Honors HAProxy PROXY protocol headers on dedicated listeners. Enable only behind a trusted proxy: a claimed source address feeds IP bans and audit logs, and a forged one lets a banned player past the ban. |
| `secrets.validate` | `true` | Requires a per-player secret, issued through the Minecraft login, for pack downloads. See [security](../security#download-authorization). A standalone host process has no login to provision secrets, so a fresh standalone config defaults this to `false`. |
| `secrets.lifetime-hours` | `336` | How long a download secret stays valid, in hours. 336 hours is 14 days. |
| `export-http.directory` | `""` | Non-empty: after every publish, the URL-contract tree (`head`, `journal`, `objects/`) is exported to this directory, ready to serve with any static HTTPS host. See [HTTP contract export](../how-it-works/hosting#http-contract-export). |
| `export-http.include-all` | `false` | Keeps every object in the HTTP contract export, including files Modrinth or CurseForge still serve to clients directly. Off, the platforms carry those downloads and your mirror holds no fallback for a file a platform later deletes; on, the exported tree stays complete. See [HTTP contract export](../how-it-works/hosting#http-contract-export). |

Setting `modpack-host` to `false` turns off every built-in listener while clients keep receiving connection information. AutoModpack cannot validate external routing from the Minecraft server process, so a reverse proxy setup is your responsibility; the [proxies page](../compatibility/proxies) covers known-good setups.

## Un-modded clients

With `require-modpack` off, players who join without AutoModpack stay in the game, and modded clients are asked whether to sync the pack when they connect.

| Setting | Default | Description |
|---|---|---|
| `nag.enabled` | `true` | Shows a chat message to players without the mod. |
| `nag.message` | `Install the AutoModpack mod to get this server's modpack!` | The message text. |
| `nag.clickable-message` | `Click here to get the AutoModpack!` | The clickable link text. |
| `nag.clickable-link` | AutoModpack on Modrinth | The URL opened on click. |
