### Is AutoModpack server-side or client-side?
Both. It needs to be installed on the server and on every client.

### How do I add client-only mods to the pack?
Put them in `automodpack/host-modpack/main/mods/` on the server. They ship to clients without the server loading them. The full guide is [building the modpack](pack-content).

### How do I restrict access to my modpack?
Keep `validateSecrets` on in the [server config](configuration/server-config), set `online-mode=true` in `server.properties`, and use the whitelist or bans as usual. Downloads then require a secret issued through the Minecraft login. See [security](security#download-authorization).

### Does it work on a LAN or a single-player world opened to others?
Yes. Generate the pack with `/automodpack generate` and start the host with `/automodpack host start`.

### Does it work with single-player worlds shared through Essential, World Host, or e4mc?
Usually not. Those mods forward Minecraft packets only, and the modpack connection has no way through them. A sharing mod would have to relay all TCP traffic or speak the AutoModpack protocol.

### Can I use extra mods alongside the pack?
Yes. Put any mod in the instance's standard `mods` folder and it loads next to the pack.

If the pack ships a mod with the same id, add the id to `pinnedModIds` in the [client config](configuration/client-config#pinned-mods) or in the "Pinned mods" screen. AutoModpack still downloads the pack copy but loads yours. Restart after changing the list. If your version breaks the pack, that is between you and the pack.

### How do I delete files from the pack?
Delete them from the server, or keep them on the server and add them to `excludedFiles`. Both are described in [building the modpack](pack-content#deleting-content). Clients remove their copy on the next update when the ownership ledger proves the file belongs to the pack.

### Can the pack delete arbitrary files from my computer?
The pack can only remove files it can prove it delivered: the path and the exact hash and size must match the pack's ownership ledger, and the file's bytes are kept on your side before deletion. Files you created or changed survive, and `saves/`, `screenshots/`, `logs/`, and `automodpack/` are always off limits. The details are in [client updates](how-it-works/client-updates#deletions-are-measured).

### Do I have to open a port on my router?
Usually not. The default `HOLEPUNCH` mode carries the modpack connection through the Minecraft login, so it needs nothing beyond the Minecraft port. The modes and their port behavior are in [hosting](how-it-works/hosting#connection-modes-and-ports).

### What happens when the server updates AutoModpack itself?
Clients follow the version the server runs: they update or downgrade through Modrinth to match it. See [AutoModpack's own updates](how-it-works/client-updates#automodpacks-own-updates).

### Which modes need a port on the server?
`HOLEPUNCH` and `MAGIC` can share the Minecraft port. `MAGIC`, `DIRECT`, and `HTTP` can also run on their own `bindPort`, and `HTTP` additionally runs fine advertise-only with the URL contract served by any static HTTPS host. The complete matrix is in [hosting](how-it-works/hosting#connection-modes-and-ports).

### Why does the pack live under `host-modpack/main/`?
Each group has a directory under `automodpack/host-modpack/<group>/`, and `main` is the default group. File rules live on each group in the `modpack` section of the [server config](configuration/server-config#groups); pasting `syncedFiles` at the top level of the config does nothing.

### What are groups?
Optional parts of a modpack, like a shader bundle or a platform-specific mod set. The server admin declares them under a category in the `modpack` section of the server config; players pick the ones they want in the in-game "Group Selection" screen, and the choice sticks across updates. They are covered in [building the modpack](pack-content#groups).

### Which Minecraft versions are supported?
The ones listed in the [latest release](https://github.com/Skidamek/AutoModpack/releases/latest).

### Is my launcher supported?
Check the [launcher list](compatibility/launchers). Prism, MultiMC forks, and Pandora additionally support modloader version sync.

### Does AutoModpack update my mods to their latest versions?
AutoModpack keeps clients identical to the server, and updating the server's mods stays your job. To update a mod, replace the jar on the server and run `/automodpack generate`; the new version reaches every client. Many downloads come straight from Modrinth and CurseForge, so mod authors see the downloads too.

### I found a bug. What should I do?
Report it on the [issue tracker](https://github.com/Skidamek/AutoModpack/issues). Include the Minecraft version, loader, and the log from the side that misbehaved.

### I found a security vulnerability. What should I do?
Report it privately to the author on [Discord](https://discordapp.com/users/464522287618457631). It will be worked on as soon as possible.
